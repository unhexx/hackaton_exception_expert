# Локальный Keycloak на стенде

Полная команда `docker compose -f deploy/fsp/compose.yaml up --build` поднимает приложение и локальный Keycloak. Локальный реалм `fsp` нужен жюри. Боевой коннектор — тот же код, направленный на issuer заказчика. Регистрация по-прежнему только по почте с подтверждением. Связь с ID участника — отдельный шаг уже вошедшего кандидата.

## Консоль

Адрес: <http://127.0.0.1:8080>. Порт опубликован только на петле `127.0.0.1:8080`.

Администратор стенда: `admin` / `admin`. Реалм `fsp`, клиент `fsp-vacancies`. Демо-пользователь реалма: `synth` / `synth`, пароль не временный. В атрибуте пользователя `fsp_external_id` записано `fsp-synth-1`: после связи в кабинете загораются достижения этого идентификатора в моке. Пароль администратора и пользователь реалма к Keycloak заказчика не относятся.

## Кнопка в кабинете

Сначала вход по почте. В кабинете кандидата, рядом с полем идентификатора, ссылка «Связь с ID участника ФСП». Она открывает стендовый Keycloak. Учётную запись из токена приложение не создаёт: писать некуда, пока анкета не сохранена.

Подпись `id_token` проверяется по JWKS issuer, алгоритм только RS256. Сверяются `iss`, срок и аудитория клиента. Токен без подписи, с чужим ключом или с истекшим сроком не записывает идентификатор. Локальный реалм отдаёт свой JWKS. Заказчик меняет четыре переменные ниже: приложение ходит на его discovery и certs, локальный контейнер для этого не нужен.

## Четыре переменные

Чужой issuer задаётся в `deploy/fsp/.env`. Это каталог compose-файла, в git файл не входит. Без него стенд берёт значения по умолчанию.

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `OIDC_ISSUER` | `http://127.0.0.1:8080/realms/fsp` | Публичный issuer: его видит браузер, с ним сравнивается `iss` |
| `OIDC_INTERNAL_ISSUER` | `http://keycloak:8080/realms/fsp` | Адрес discovery и обмена кода из контейнера приложения |
| `OIDC_CLIENT_ID` | `fsp-vacancies` | Client id |
| `OIDC_CLIENT_SECRET` | пусто | Пустой секрет значит публичный клиент, PKCE S256 |

У заказчика в клиенте тот же redirect `http://127.0.0.1:8000/auth/fsp/callback`, authorization code и PKCE, если клиент публичный. Идентификатор участника кладётся в claim `fsp_external_id`. Если claim пустой, в профиль попадёт `sub`.

Локальный контейнер при своём issuer не нужен. Сервис `app` от Keycloak не зависит, поэтому команда ниже его не поднимает:

```
docker compose -f deploy/fsp/compose.yaml up --build app
```

Команда без имени сервиса по-прежнему поднимает локальный реалм. Это путь жюри.
