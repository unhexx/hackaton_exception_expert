# Локальный реалм на стенде

Полная команда `docker compose -f deploy/fsp/compose.yaml up --build` поднимает приложение и локальный issuer реалма `fsp`. Реалм нужен жюри для связи ID участника. Боевой коннектор — тот же код, направленный на issuer заказчика. Регистрация по-прежнему только по почте с подтверждением. Связь с ID участника — отдельный шаг уже вошедшего кандидата.

Образ `quay.io/keycloak/keycloak` стенд не скачивает. При распаковке слой `lib/lib/deployment` пишет `no space left on device`, и `up --build` обрывается до кабинетов. Вместо образа поднят короткий процесс на Python из `product/stand_oidc.py`: discovery, форма входа, PKCE S256, обмен кода и подпись RS256. Пользователи и redirect читаются из `deploy/fsp/fsp-realm.json` на сборке образа `fsp-oidc`. Имя сервиса в compose остаётся `keycloak`, чтобы адрес из контейнера приложения не менялся: `http://keycloak:8080`.

## Страница реалма

Адрес: <http://127.0.0.1:8080>. Порт опубликован только на петле `127.0.0.1:8080`.

Консоли администратора Keycloak на стенде нет. Страница объясняет, что это локальный issuer, и принимает демо-пользователя реалма: `synth` / `synth`. В атрибуте `fsp_external_id` записано `fsp-synth-1`: после связи в кабинете загораются достижения этого идентификатора в моке. Пароль демо-пользователя к Keycloak заказчика не относится.

## Кнопка в кабинете

Сначала вход по почте. В кабинете кандидата, рядом с полем идентификатора, ссылка «Связь с ID участника ФСП». Она открывает форму локального реалма. Учётную запись из токена приложение не создаёт: писать некуда, пока анкета не сохранена.

Подпись `id_token` проверяется по JWKS issuer, алгоритм только RS256. Сверяются `iss`, срок и аудитория клиента. Токен без подписи, с чужим ключом или с истекшим сроком не записывает идентификатор. Локальный реалм отдаёт свой JWKS. Заказчик меняет четыре переменные ниже: приложение ходит на его discovery и certs, локальный контейнер для этого не нужен.

## Четыре переменные

Чужой issuer задаётся в `deploy/fsp/.env`. Это каталог compose-файла, в git файл не входит. Без него стенд берёт значения по умолчанию.

| Переменная | По умолчанию | Смысл |
| --- | --- | --- |
| `OIDC_ISSUER` | `http://127.0.0.1:8080/realms/fsp` | Публичный issuer: его видит браузер, с ним сравнивается `iss` |
| `OIDC_INTERNAL_ISSUER` | `http://keycloak:8080/realms/fsp` | Адрес discovery и обмена кода из контейнера приложения |
| `OIDC_CLIENT_ID` | `fsp-vacancies` | Client id |
| `OIDC_CLIENT_SECRET` | пусто | Пустой секрет значит публичный клиент, PKCE S256 |

У заказчика в клиенте тот же redirect `http://127.0.0.1:8000/auth/fsp/callback`, authorization code и PKCE, если клиент публичный. Идентификатор участника кладётся в claim `fsp_external_id`. Если claim пустой, в профиль попадёт `sub`.

Локальный контейнер при своём issuer не нужен. Сервис `app` от него не зависит, поэтому команда ниже его не поднимает:

```
docker compose -f deploy/fsp/compose.yaml up --build app
```

Команда без имени сервиса по-прежнему поднимает локальный реалм. Это путь жюри.
