# Постановка заказчика

Источник: сообщение в рабочем цикле, 2026-09-28. Ниже формулировки заказчика. То, чего здесь нет, в требования не возводить.

## Название

Цифровая платформа-агрегатор ИТ-вакансий с верифицированным профилем достижений участника Федерации спортивного программирования (ФСП).

## Актуальность

Существующие площадки поиска работы универсальны и не решают задачу ни одной из сторон. Работодатель вручную фильтрует нерелевантные отклики силами технических специалистов. Кандидат откликается вслепую и не получает обратной связи. Формальное резюме фиксирует стек и места работы, но не подтверждает практическую компетентность, поэтому отбор сводится к ключевым словам. Стек, грейд, роль в команде и формат работы на универсальных платформах не формализованы.

Отдельный сервис под ИТ должен говорить с обеими сторонами на профессиональном языке, повысить точность подбора и сократить сроки. Подтверждаемость квалификации — дополнительное преимущество. У ФСП есть данные о результатах участников соревнований и мероприятий: объективное, проверяемое подтверждение практических навыков. Обогащение профиля этими достижениями даёт работодателю ориентир, а участнику — способ конвертировать соревновательный опыт в карьерное преимущество.

## Задача

Веб-сервис: отраслевой агрегатор вакансий для ИТ-специалистов с обратной механикой подбора. Соискатели автоматически категоризируются по объективно подтверждаемому профилю. Работодатель сам находит нужную категорию и выходит на конкретного кандидата с вакансией и заработной платой.

## Ресурсы, которые организатор обещает на хакатоне

Так было в сообщении 2026-09-28:

- Спецификация интеграции с информационными системами ФСП (описание API и/или тестовый мок) для достижений участников: дисциплины, соревнования, результаты, роли, разряды.
- Дизайн-макеты и брендбук ФСП: фирменный стиль, логотипы, гайдлайны, UI-макеты.
- Консультации профильных специалистов и экспертов ФСП: предметная область, структура данных о соревнованиях, требования к продукту.

ТЗ.pdf, раздел 4, это сужает. API реестра и описание структуры данных на хакатоне не выдаются. Брендбук — фирменный стиль и логотипы, без жёстких правил вёрстки. Консультации экспертов остаются. Макеты экранов в полученном брендбуке не пришли. Что из этого следует для разработки — в [01-requirements.md](01-requirements.md), без повтора здесь.

## Компетенции команды

- Product/project manager. В команде из 2–3 человек может совмещаться с любой другой ролью.
- Backend-developer.
- Frontend-developer.
- Data Scientist / ML-engineer: матчинг, разбор резюме, механизм тестирования.
- UX/UI-designer. В команде из 2–3 человек опционален: можно опереться на брендбук и макеты ФСП.

Работающий прототип (MVP) веб-сервиса, развёрнутый и доступный для демонстрации. Вместе с ним: исходный код, документированный API, инструкция по развёртыванию, краткая техническая документация.

## Уточнение механики

Второе сообщение организатора называет тот же трек и ту же обратную механику двумя шагами: соискатели автоматически категоризируются по объективно подтверждённому профилю; работодатель сам находит категорию и выходит на конкретного кандидата с оффером и прозрачной заработной платой.

## Уточнение из ТЗ.pdf

Файл `ТЗ.pdf` в корне репозитория, титул «Техническое задание 2026». Это тот же продукт. Календарь ниже ТЗ не переписывает. Перечень для разработки — в [01-requirements.md](01-requirements.md), каждый новый пункт помечен источником. Здесь только то, чего не было во втором сообщении:

- Категория собирается опросом по специализации и тестом на заявленный грейд, не текстом резюме. Достижения ФСП поднимают человека внутри категории. Профиль без истории ФСП тоже обязателен.
- Задача не сводится к парсингу чужих сайтов. Свои вакансии и самостоятельный отклик для минимального объёма не обязательны.
- Уровень оплаты в приглашении — обязательный диапазон. Форма числа записана в требованиях, не здесь.
