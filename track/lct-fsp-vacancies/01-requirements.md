# Требования к прототипу

Читать после [00-postanovka.md](00-postanovka.md). Пункты с пометкой «следствие» выведены из текста заказчика, чтобы был реализуемый срез. Если следствие мешает демо, его режет product, а не разработчик по ходу кода.

Открытые вопросы не заполнять выдуманным API. Список: [03-open-questions.md](03-open-questions.md).

## Продукт

Отраслевой веб-сервис подбора в ИТ. Главная механика обратная: не соискатель рассылает отклики, а работодатель выбирает категорию подтверждаемого профиля и сам выходит на человека, прикладывая вакансию и заработную плату.

Название говорит «агрегатор вакансий». В описании задачи внешний сбор вакансий с других площадок не задан. Для MVP вакансия живёт внутри предложения работодателя. Импорт чужих досок — вне скоупа, пока product не снимет вопрос Q1.

## Приёмка MVP

Демонстрация на развёрнутом стенде, без ручной правки базы во время сценария.

1. Соискатель открывает профиль. Достижения подтягиваются из контура ФСП (на хакатоне — из мока, пока нет боевого API).
2. Профиль получает категорию. У категории есть человекочитаемое объяснение, из каких подтверждённых фактов она собрана.
3. Работодатель открывает категорию, видит кандидатов этой категории и отправляет конкретному человеку предложение: вакансия и заработная плата.
4. Соискатель видит входящее предложение.
5. Рядом с кодом лежат описание API, инструкция развёртывания и короткая техническая записка. Сервис поднимается по инструкции на чистой машине.

## Акторы

| Актор | Может | Не может |
|-------|--------|----------|
| Соискатель | Вести свой профиль, видеть свои достижения и входящие предложения | Видеть чужие предложения и закрытые профили |
| Работодатель | Искать по категориям, смотреть открытые карточки, слать предложение с вакансией и зарплатой | Менять достижения ФСП и категорию вручную |
| Контур ФСП | Отдавать дисциплины, соревнования, результаты, роли, разряды | Принимать от нас назначение разряда |
| Категоризатор | Класть соискателя в категорию по правилам версии N | Подменять отсутствие данных ФСП текстом резюме |

Достижение помечается как подтверждённое только если оно пришло из контура ФСП. Текст резюме подтверждением не является.

## Профиль, на котором говорит отрасль

Поля, без которых задача заказчика не выполняется (следствие из абзаца про стек, грейд, роль и формат):

- стек (набор меток, не свободный абзац);
- грейд из закрытого списка;
- роль в команде, которую человек готов занимать;
- формат работы.

Эти поля вводит соискатель. Они участвуют в карточке и в фильтрах. Они не превращают профиль в «верифицированный», если блок ФСП пуст.

## Контракт данных ФСП до прихода спецификации

Рабочая гипотеза для мока. Имена полей можно сменить одним адаптером, когда приедет API. Смысл полей не выкидывать: он назван заказчиком.

```text
Participant
  external_id
  display_name
  rank                # строка разряда, как отдала ФСП
  results[]
    competition_id
    competition_name
    discipline          # одна из дисциплин вида спорта
    role_in_team        # роль на соревновании, не путать с ролью в компании
    place               # место или иной итог, как отдала ФСП
    held_on             # дата
```

Сервис не вычисляет спортивный разряд из места. Разряд хранится и показывается как утверждение источника.

Категория:

```text
CategoryAssignment
  profile_id
  category_id
  rule_version
  explanation         # какие факты ФСП и какие поля профиля сработали
  scored_at
```

Предложение:

```text
Offer
  employer_id
  profile_id
  category_id
  vacancy_title
  salary_min
  salary_max
  salary_currency
  message
  status              # sent | seen
```

Зарплата обязательна и видна соискателю на входящем оффере: организатор требует прозрачную заработную плату. Валюта по умолчанию RUB, пока Q2 не закрыт. «По договорённости» прозрачной вилкой не считается.

## Матчинг и разбор резюме

Компетенция DS задана заказчиком явно: матчинг, разбор резюме, механизм тестирования.

- Матчинг MVP: правила категории по дисциплине, разряду и роли на соревновании плюс фильтр по стеку, грейду, роли в команде и формату. Версия правил фиксируется в `rule_version`.
- Разбор резюме: из текста достаются те же отраслевые поля, чтобы человек не вбивал стек руками. Разобранное поле помечается `source=resume` и не получает метку верификации ФСП.
- Механизм тестирования MVP: воспроизводимый прогон на зафиксированном наборе профилей. Команда печатает, сколько категорий совпало с ожиданием и сколько резюме разобрано без падения. Это проверка механизма, не экзамен соискателя. Экзамен в продукт не входит, пока открыт Q3.

Если данных ФСП нет, категория «без подтверждения» допустима и в выдаче работодателя отделена от подтверждённых. Прятать таких людей внутрь подтверждённой категории нельзя.

## Нефункциональные ограничения MVP

- Веб, доступный по URL на время демо.
- API описано рядом с кодом (маршрут, тело, код ответа, пример).
- Персональные достижения не отдаются работодателю, пока соискатель не открыл профиль. Мок с реальными ФИО в репозиторий не класть.
- Секреты боевой ФСП в git не коммитить. Мок работает без них.
- Сроки — в [00-postanovka.md](00-postanovka.md). Код решения замирает в стоп-код 11.10.2026, 23:59 МСК. Доработку 19–21.10 ведут только команды из ТОП-10, опубликованного 18.10, и только по замечаниям экспертов.

## Вне скоупа MVP

- Парсинг hh.ru и других досок.
- Присвоение спортивных разрядов и званий.
- Мобильное приложение.
- Чаты, видеозвонки, кадровый документооборот.
- Рекомендательная лента «вам подойдёт» без явной категории и без зарплаты в предложении.
- Обучение большой модели с нуля.

## Демо-скрипт

Один проход на три минуты, его пишет product и кладёт в `track/lct-fsp-vacancies/demo.md`, когда появятся живые экраны.

1. Профиль участника с разрядом и двумя результатами разных дисциплин.
2. Категория и одна фраза, почему человек в ней.
3. Кабинет работодателя: та же категория, предложение с вилкой зарплаты.
4. Кабинет соискателя: предложение на месте.
