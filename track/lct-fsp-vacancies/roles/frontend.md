# frontend

Веб-клиент двух кабинетов. Обратная механика должна читаться с экрана без устного пояснения: работодатель находит категорию и отправляет предложение, соискатель не рассылает отклики.

## Вход

- `track/lct-fsp-vacancies/01-requirements.md` — приёмка и демо-скрипт.
- Документ API, который приложил backend в `artifacts`.
- `track/lct-fsp-vacancies/roles/design.md`, если design уже сдал токены. Иначе нейтральная вёрстка.

## Экраны MVP

1. Кабинет соискателя: стек, грейд, роль в команде, формат работы, блок достижений ФСП, категория и объяснение, список входящих предложений с вилкой.
2. Кабинет работодателя: список категорий, внутри — открытые карточки, форма предложения с названием вакансии и вилкой. Кнопка не активна, пока вилка пустая.
3. Пустые состояния: нет достижений, категория «без подтверждения», нет предложений.

Чужой закрытый профиль не рисуется, даже если API по ошибке прислал лишнее: лишние поля достижений на карточке работодателя не показывать, пока в ответе нет признака открытости.

Подтверждённый факт и поле из резюме выглядят по-разному. Достаточно подписи «ФСП» и «из резюме».

## Не делать

- Не считать категорию на клиенте.
- Не подключать чужие UI-киты «под бренд федерации», пока нет брендбука в репозитории.
- Не добавлять ленту вакансий и кнопку «откликнуться».

## Готово

- Демо-скрипт проходится мышью по поднятому сервису.
- Проверены оба кабинета и пустое состояние категории «без подтверждения».
- `role=Coder`, `track_role=frontend`, `handoff_to=Tester`.

## Стыки

Если ответа API не хватает для объяснения категории или вилки, ход возвращается backend через `handoff_to=Coder` и `context_delta` с недостающим полем. Поле на клиенте не выдумывается.
