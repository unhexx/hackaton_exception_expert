# matching

Data Scientist / ML-engineer. Три работы заказчика: матчинг, разбор резюме, механизм тестирования. В MVP это правила категории, разбор текста резюме в поля профиля и воспроизводимый отчёт качества.

## Вход

- `track/lct-fsp-vacancies/01-requirements.md` — раздел «Матчинг и разбор резюме».
- Контракт профиля, который отдал backend.
- `track/lct-fsp-vacancies/02-domain.md` — только таблица дисциплин и список разрядов.

## Правила категории v1

Категория объяснима без модели. Пример формы объяснения, не сам перечень категорий: «алгоритмическое программирование, разряд не ниже I, стек содержит выбранные метки».

- Вход правила: результаты ФСП, разряд-как-строка, поля профиля.
- Выход: `category_id`, `rule_version`, `explanation`.
- Нет результатов ФСП → категория «без подтверждения». Резюме этот исход не перебивает.
- Несколько дисциплин → одна основная категория по правилу, остальные дисциплины остаются в карточке достижений. Прятать их нельзя.

Список категорий v1 согласует product до кода. Если списка нет, matching предлагает не больше шести категорий по дисциплинам из доменной справки и отдаёт список product. Сам в прод его не включает.

Разбор резюме заполняет стек, грейд, роль в команде и формат, каждое поле с `source=resume`. Неизвестное значение остаётся пустым, а не угадывается по созвучию.

## Механизм тестирования

Золотой набор: несколько синтетических профилей и ожидаемый `category_id`. Команда прогона печатает число совпадений и число резюме, которые разобрались до конца. Набор лежит в репозитории, прогон не ходит в сеть и не в боевую ФСП.

Падение качества относительно последнего зафиксированного отчёта — повод вернуть ход себе, а не ослабить ожидание в наборе.

## Не делать

- Не обучать модель ради прототипа.
- Не вычислять спортивный разряд.
- Не строить экзамен и прокторинг, пока Q3 открыт.
- Не читать закрытые профили «для улучшения модели».

## Готово

- Чистая функция категории покрыта золотым набором.
- Разбор резюме не ставит метку верификации.
- Отчёт прогона приложен в `artifacts`.
- `role=Coder`, `track_role=matching`, `handoff_to=Tester`.

## Стыки

Backend сохраняет результат функции и не дублирует правила у себя. Frontend показывает `explanation` строкой, без повторного расчёта.
